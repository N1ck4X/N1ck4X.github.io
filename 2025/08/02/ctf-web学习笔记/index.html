ctf-web学习笔记

2025-08-02- 2025-08-10
ctf-web

第一节 基础储备

约定

作为CTF-WEB的课程元素，有以下约定：
flag 指题目答案，有一个固定的字符串组成
poc 指漏洞演示，一般不具有攻击性，仅仅证明漏洞存在
exp 指漏洞利用脚本、工具，具有攻击性，可以直接进行漏洞利用，执行命令或读取文件
脚本 指利用漏洞需要执行的本地程序，方便漏洞利用者替代重复手工操作

第二节 认识漏洞

漏洞及其产生原因

漏洞是指对现有信息资产的非预期使用，用户通过技术手段，访问或者修改到本不应该访问到的数据，执行本不应该执行的代码。

漏洞产生的原因有：
设计缺陷
逻辑错误
代码bug
越权漏洞
其他漏洞

漏洞利用方式

失能

低级危害的利用方式，让对方资产暂时失去服务能力，一般不会有其他损失，技术损失小，无形资产损失大

读取

中级危害的利用方式，能够读取目标资产中的敏感数据

写入

高级危害的利用方式，不仅能读取敏感数据，还能通过写入数据篡改目标数据，修改对外页面。危害性、影响性大

执行

最高级别危害的利用方式，可以在目标资产上执行任意命令，完全控制目标资产，控制内部其他资产，不仅对数据洗劫一空，甚至可以操作目标指令，造成巨大损失。

web做题思路

判断利用的漏洞方式：读取、写入、还是执行，没有思路的时候按从低到高：先找文件读取，再找文件写入、再找文件执行。大概确定最重要拿到的权限，确定渗透方向。

判断漏洞大概类型，确定具体的利用思路，实现漏洞利用。

寻找敏感数据，最终拿到flag。

第三节 漏洞利用之信息泄露

信息泄露的类型

  1. 版本泄露
    .git、.svn、.hg、.bzr、CVN
  2. 敏感文件泄露
    robots.bit、www.zip、静态文件注释泄露
  3. 配置错误信息泄露
    DS_Store、WEB-INF、Apache\Nginx 配置错误

以上只是一些例子和思路，但不仅仅只有这些

信息泄露漏洞利用

http头信息泄露

区别 /admin/ 与 /admin：
/admin/表示访问的是admin目录，会默认访问admin文件里的索引文件
/admin表示访问的是admin文件，如果没有这个文件，就直接返回404，不会寻找索引文件
如果有专门设置，两种情况都能访问/admin/

目前大多数网站都是基于路由：
URL与路由（域名后第一个斜杠开始到结束）
直接用/user后面没有后缀就不是访问的文件而是路由
有些网站两种都有

状态码：200（正常）、301（跳转）、302（跳转）、403（文件存在但禁止访问）、404（文件不存在）、500（服务器内部错误）、502（转发失败）

报错信息泄露

利用报错信息泄露服务器状态；思路：输入不能使其正常运行的语句，让其给出报错信息。

页面信息泄露

页面信息泛指浏览器获得的页面数据总和，由于浏览器看到的页面是渲染后的页面，我们看到的文字格式，图片，表格，其实是对HTML代码渲染后的结果，有些内容我们不一定能在页面上看得到，需要看源文件。

robots.txt敏感文件泄露

关于robots协议详解
使用：URL/robots.txt 例如：https://Baidu.com/robots.txt
不允许的路径往往都隐藏着敏感信息，给爬虫一个思路去寻找敏感信息

.git文件泄露

git是一个版本控制系统
版本控制系统（Version Control System，VCS）是一种用于跟踪和管理文件变更的软件工具，它通过记录文件的修改历史、支持多版本并行开发、协调团队协作以及提供版本回退能力，实现对源代码或其他数字资产的系统化管控。常见的类型包括集中式（如SVN）和分布式（如Git）。

核心功能：

  1. 版本追踪：记录每次修改的元数据（作者、时间、变更内容）
  2. 分支管理：支持创建独立开发线（branch）并合并（merge）
  3. 冲突解决：检测并处理多人同时修改的冲突
  4. 版本回滚：可恢复到任意历史版本
  5. 协作支持：允许多开发者通过远程仓库同步工作

通俗例子：
想象一个小组共同撰写一份电子版调研报告：

  1. 无版本控制：

    • 大家轮流修改同一文件，可能覆盖他人内容
    • 文件命名变成”报告_终版_FINAL_真的最后版.docx”
    • 无法确认谁修改了哪个部分

  2. 使用版本控制后：

    • 系统自动记录每次修改（如：”小明2023-08-20增加结论部分”）
    • 成员A修改引言时，成员B可同时修改数据章节
    • 错误删除内容时可一键恢复昨天版本
    • 通过”提交留言”清楚记录每次修改目的
    • 最终自动合并所有人的修改，冲突处会高亮提示

这就如同游戏存档系统：既能随时回到之前的关卡状态（版本回退），又能尝试不同剧情分支（分支开发），最后把所有最佳选择合并成完美结局（代码合并）。

信息泄露总结

信息泄露考点：

  1. robots.txt泄露（里面有可疑路径或者敏感文件名称）
  2. git/svn泄露（访问.git或者.svn目录出现403）
  3. 页面注释泄露（右键查看页面源代码）、http头泄露（类似百度的BWS/1.1)
  4. 任意文件下载造成的信息泄露（可以下载WEB-INF文件夹里内容）
  5. 开源社区信息泄露，例如：泄露出项目名称，而整个项目代码可以在github、gitee里面找到）
  6. 使用vim异常退出，可能存在类似.index.php.swp临时文件

BP爆破

什么是爆破
爆破其实就是尝试，如果存在下面的逻辑就能爆破
例如，登录逻辑中，只要没有验证码，我们就可以在无限次尝试中有概率试出正确用户名密码。爆破的关键就是多次尝试。那么相应的，应对爆破就是防止多次尝试：

  1. 图形验证码
  2. 手机短信验证码
  3. 无感验证码
  4. 等等
    也就是说，如果存在一个逻辑，可以接受一个参数，并且判断这个参数对不对，在不限次情况下，我们可以试出参数的值。

BP爆破单个参数

BP爆破用户名密码
利用口令字典爆破，口令字典（Password Dictionary）是网络安全和密码破解领域使用的一种工具，它本质上是一个包含大量常见密码、短语和字符串组合的文本文件。
